# 설비 동작 시뮬레이션 구현 계획서

- 대상: InoRobot Assistant `2_3DSimulation`
- 작성일: 2026-10-01
- 목적: 컨베이어 이송, 외부 축 모듈, 실린더 전진·후진, 그리퍼 개폐를 로봇 동작 및 I/O와 연동한다.
- 문서 상태: 구현 제안. 이번 작업은 계획서 작성이며 아래 기능을 새로 구현한 상태는 아니다.

## 1. 구현 방향

사용자가 불러온 CAD 모델에 **움직이는 부품, 이동 방향, 이동량, 제어 신호**를 지정하면 설비로 동작하도록 한다. 컨베이어·실린더·그리퍼마다 별도 애니메이션을 만드는 대신 공통 직선·회전 기구와 물체 소유권 관리 위에 설비별 동작을 구성한다.

첫 구현은 위치와 시간에 따른 기구학 시뮬레이션으로 진행한다. 지정된 속도·행정·센서 위치에 따라 움직이고 공정 순서를 검증하는 것이 목적이다. 마찰, 중력 낙하, 공압 압력, 접촉력 계산은 후속 범위로 둔다. 화면에서 물체가 움직이는 것과 로봇이 이동 중인 물체를 추적하여 집는 컨베이어 트래킹은 별도 단계로 구분한다.

대표 완료 시나리오:

> 컨베이어 운전 → 물체 이송 → 감지 센서 ON → 컨베이어 정지 → 실린더 전진 → 로봇 접근 → 그리퍼 닫힘·물체 파지 → 로봇 이송 → 그리퍼 열림·물체 배치 → 실린더 후진 → 다음 물체 이송

## 2. 현재 코드에서 재사용할 기능

2026-10-01 현재 작업공간의 소스를 기준으로 조사했다. 기존 미커밋 변경이 있는 상태이므로 실제 구현 시작 시 당시 변경 사항과 기준 동작을 다시 확인한다.

| 현재 구성 | 확인한 기능 | 추가할 부분 |
|---|---|---|
| `main.js`의 `animate()` | 컨트롤러·로봇 모션 갱신, 충돌 검사, 렌더링 | 설비 런타임과 센서 갱신 연결 |
| `requiresContinuousRendering()` | 실행 상태에 따른 연속 렌더링 | 로봇이 멈춰 있어도 움직이는 설비의 갱신 유지 |
| `io-simulator-core.mjs` | IN/OUT 비트·바이트·워드 표시와 값 변환 | 설비 명령과 피드백의 주소 연결 |
| `io-function-mapping-core.mjs` | `GRIP_USE`, `GRIP_RELEASE`, `VIEW` 매핑 | 설비 명령 지원과 기존 매핑 호환 |
| `main.js`의 파지 관련 함수 | 물체 부착·해제, 프로그램 파지 동작, 컨트롤러 접촉 기반 파지 추론 | 실제 그리퍼 부품 개폐, 파지 조건, 중복 제어 방지 |
| `applyRobotTravelAxis()` | E1~E3으로 로봇 전체 X/Y/Z 이동, E4~E6으로 로봇 전체 회전 | 가동 테이블·회전축 모델과 실제 축 기구 연결 |
| `olp-runtime.mjs` | 로봇 프로그램 실행, I/O 조건 대기, 일시정지 | 설비와 시간·실행 상태 연동 |
| `collision-system.mjs` 및 충돌 갱신 경로 | 메시 충돌 검사와 로봇 모션 충돌 처리 | 설비 가동부·이송 물체 갱신, 설비 정지 정책 |
| 작업공간 저장·복구 및 모델 ID | 모델·외부 축·파지 물체 저장 경로 | 설비 정의·부품 참조·소유권·초기 상태 저장 |

기존 파지 기능을 새 기능으로 중복 구현하지 않는다. 현재 외부 축은 로봇 루트에 적용되는 이동·회전이므로, 이를 곧바로 임의의 외부 축 모듈 지원으로 간주하지 않는다.

## 3. 사용자가 설정하는 흐름

1. CAD 또는 기본 도형으로 설비를 배치한다.
2. 모델 트리 또는 우클릭 메뉴에서 `설비 동작 설정`을 연다.
3. 설비 종류를 컨베이어 / 직선 축 / 회전 축 / 실린더 / 그리퍼 중 선택한다.
4. 고정부와 가동부를 선택한다. 선택한 부품은 색상으로 강조한다.
5. 모델 기준 이동축·회전 중심·행정·속도를 지정한다. 방향 화살표와 시작·끝 위치를 미리 표시한다.
6. 수동 시험으로 전진·후진, 열기·닫기, 운전·정지 등을 확인한다.
7. 제어 OUT와 센서 IN을 연결한다.
8. 전체 시뮬레이션에서 로봇 프로그램과 함께 실행하고 작업공간을 저장한다.

공통 화면에는 현재 위치, 목표 위치, 운전 상태, 명령 신호, 완료 신호, 오류 원인을 표시한다. 실행 중에는 기구 구조와 기준 위치 편집을 잠그고 정지 후 변경한다.

CAD가 한 개의 메시로 합쳐져 있으면 가동부를 자동으로 알아낼 수 없다. 초기 버전은 분리된 부품 선택 또는 별도 가동부 파일 불러오기를 지원하고, 자동 형상 분해는 후속 기능으로 둔다. 기존 부품 복사 기능을 이용하는 경우 원본과 복사본이 동시에 보이거나 충돌 대상으로 중복 등록되지 않도록 해야 한다.

## 4. 공통 기구·런타임 설계

### 4.1 설비 정의와 실행 상태 분리

설비 정의에는 다음 정보를 둔다.

- 영구 설비 ID, 이름, 종류, 모델 및 부품 ID
- 고정 프레임, 가동부 목록, 가동부의 초기 로컬 변환
- 직선·회전 축, 회전 중심, 최소·최대 위치, 초기 위치
- 속도, 가속·감속 설정, 완료 허용오차
- 명령·센서 I/O 연결 및 제어 출처
- 파지 영역, 이송 영역, 연결 설비 및 물체 인계 조건

실행 상태에는 현재·목표 위치, 현재 속도, 실행 상태, 활성 명령, 소유 물체, 오류, 시뮬레이션 시간을 둔다. `정지`, `이동 중`, `완료`, `오류`를 구분하고 양방향 명령 동시 입력 등의 오류를 화면에 표시한다.

설정 단위는 mm, mm/s, mm/s², deg, deg/s, deg/s², 초로 통일한다. 모델 로컬축과 World축을 구분하고 기존 장면의 Z-up 좌표 규칙을 유지한다. 변환은 매 프레임 누적하지 않고 초기 변환과 현재 축 위치로 계산하여 반복 실행 오차를 줄인다.

### 4.2 공통 시뮬레이션 시간

고정 시간 간격으로 상태를 갱신하고 화면은 그 결과를 렌더링한다. 초기 제안은 1/60초이며 실제 부하와 속도에 따라 조정한다. 렌더링 FPS가 달라도 같은 시뮬레이션 시간에 같은 위치가 나와야 한다.

갱신 순서는 명령 수집 → 로봇·설비 이동 → 부착 물체 변환 갱신 → 충돌·센서 판정 → 피드백 입력 반영 → 화면 표시로 정의한다. 프로그램은 다음 갱신에서 센서 결과를 읽는다. 기존 로봇 모션이 별도 애니메이션 경로를 사용하는 부분은 시간 어댑터를 연결하고, OLP의 대기·타이머까지 함께 점검해야 한다.

일시정지하면 로컬 로봇·설비·타이머를 함께 멈추고 재개 시 지나간 실제 시간을 따라잡지 않는다. 백그라운드 탭의 긴 시간 간격은 자동 일시정지하여 물체가 순간 이동하지 않게 한다. 단순 정지는 현재 위치를 유지하고, 초기화는 실행 시작 시 저장한 위치·소유권·시뮬레이터가 관리하는 센서 상태를 복원한다.

실제·가상 컨트롤러 연결에서는 외부 장치의 시계를 로컬 시간 배율로 바꿀 수 없으므로 1배속 관측을 기본으로 한다. 로컬 일시정지를 외부 컨트롤러 정지로 취급하지 않는다. 외부 제어 중에는 로컬 수동 명령과 자동 명령의 동시 구동을 차단한다.

### 4.3 물체 소유권과 인계

공작물은 한 시점에 World, 컨베이어, 그리퍼, 외부 축·치구 중 하나만 소유할 수 있다. 소유권 변경은 한 번의 원자적 처리로 수행한다.

- 그리퍼가 집으면 컨베이어 이송 목록에서 즉시 제외한다.
- 그리퍼가 놓으면 적합한 배치 영역의 설비로 인계한다. 대상이 없으면 World 위치를 유지한다.
- 부모 프레임을 바꿀 때 World 위치·회전·크기를 보존하고 새 부모 기준 로컬 변환을 계산한다.
- 기존 파지 부착·해제, I/O 파지 매핑, 접촉 기반 자동 파지가 같은 물체에 중복 적용되지 않도록 공통 소유권 경로를 사용한다.
- 기존 부품 복사로 생성된 파지 물체도 하나의 공작물 ID로 추적하여 원본·복사본이 동시에 이송되지 않도록 한다.
- 여러 로봇이 동시에 집으려는 경우 우선 완료된 유효 파지만 성공시키고 나머지에는 실패 상태를 알린다.

## 5. 설비별 구현 범위

### 5.1 컨베이어

설정: 이송 방향, 길이·폭·운반 높이, 속도, 운전·역운전 신호, 공작물 목록 또는 투입 영역, 감지 영역, 끝단 처리 정책.

1차는 직선 컨베이어와 명시적으로 등록한 공작물을 지원한다. 컨베이어의 로컬 방향을 World로 변환하여 물체를 `속도 × 경과 시간`만큼 이동시킨다. 컨베이어를 회전 배치해도 물체가 올바른 방향으로 움직여야 한다. 물체가 움직이는 동안 고정부 모델은 움직이지 않는다.

끝단 도달 시 기본은 끝 위치 정지로 한다. 후속으로 다음 컨베이어 인계, 공정 이탈, 반복 투입을 제공하되 물체 삭제·재생성은 사용자가 선택한 정책에서만 수행한다. 정·역운전 동시 입력은 설정 오류로 처리한다.

센서는 공작물의 간단한 경계 형상과 감지 영역의 겹침으로 판단한다. 빠르게 지나가는 물체의 누락을 막기 위해 이전·현재 위치 사이의 통과도 검사한다. 초기 버전은 접촉·미끄럼·물체 간 적체를 계산하지 않고 물체 간격을 사용자가 설정한다.

2차는 영역 기반 자동 등록과 컨베이어 간 인계를 지원한다. 곡선·분기·적체는 후속 범위다. 로봇의 실시간 컨베이어 트래킹은 별도 위치·엔코더 모델과 좌표계 연동 검증 후 구현한다. 1차 공정은 물체를 정지시킨 뒤 집는 방식으로 검증한다.

### 5.2 외부 축 모듈

직선 레일, 리프트, 회전 테이블을 공통 1자유도 기구로 구현한다. 고정부는 유지하고 가동부 및 탑재물만 움직인다. 축 방향·회전 중심·영점·범위·속도·가속도·탑재 대상을 지정한다.

제어 방식은 두 종류를 지원한다.

- 독립 설비 축: 수동 위치 명령 또는 설비 명령으로 구동한다.
- 로봇 연동 축: 지정한 로봇의 E축 값을 받아 모듈을 구동한다.

기존 E1~E3 직선 이동·E4~E6 회전 방식은 기존 작업공간의 기본 동작으로 유지한다. 새 모듈을 연결한 축만 모듈 프레임이 변환을 담당하고, 동일 E값이 로봇 루트에도 다시 적용되는 이중 이동을 막는다. 새 축 설정은 번호별 직선/회전 종류와 단위를 명시한다.

로봇 탑재 레일에서는 Robot Base, TCP, JOG, IK, OLP 목표 변환, 충돌, Trace 및 저장·복구를 함께 확인한다. 회전 치구의 작업 좌표계는 가동 프레임을 따라가도록 연결해야 한다. 이는 로봇과 포지셔너의 동시 보간·협조 제어와 별개이며, 완전한 협조 제어는 후속 단계로 둔다.

### 5.3 실린더

설정: 본체, 로드·로드에 연결된 부품, 로컬 이동축, 행정, 초기 위치, 전진·후진 속도, 명령 방식, 전진·후진 완료 센서.

- 전진·후진 명령으로 목표 위치를 변경하고 설정 속도로 이동한다.
- 완료 센서는 명령 즉시 켜지지 않고 실제 끝 위치에 도달하면 켜진다. 중간 위치에서는 양쪽 완료 센서가 꺼진다.
- 이동 중 반대 명령을 받으면 현재 위치에서 방향을 바꾼다.
- 2신호 제어와 단일 신호 제어를 구분한다. 2신호의 양쪽 ON은 오류, 양쪽 OFF는 기본 현재 위치 유지다. 단일 신호의 OFF 후 동작은 스프링 복귀 등 설정에 따른다.
- 초기 버전은 속도 기반으로 움직이고 압력·부하·완충 효과는 계산하지 않는다.

### 5.4 그리퍼

설정: 본체, 각 손가락 가동부, 손가락별 이동축 또는 회전축, 열림·닫힘 위치, 속도, 파지 영역, 허용 공작물, 개폐 명령, 열림·닫힘 완료·파지 감지 센서.

첫 구현은 평행 2지 그리퍼를 대상으로 하되 공통 축 구조는 여러 가동부를 지원한다. 각 손가락의 이동량을 별도로 설정하여 총 개구폭과 손가락별 행정을 혼동하지 않게 한다.

손가락이 파지 위치에 도달하고 유효 공작물이 파지 영역에 있을 때 기존 물체 부착 기능을 통해 파지한다. 그리퍼가 닫혔다는 상태와 실제 공작물을 잡았다는 상태를 구분한다. 공작물별 파지 개구폭 또는 접촉 허용오차를 설정하여 손가락이 물체를 관통한 뒤 잡는 표현을 방지한다.

열림 명령 후 설정한 해제 개구폭을 넘으면 물체를 해제한다. 해제 물체는 배치 영역 또는 World로 인계하고 초기 버전에서는 중력 낙하를 적용하지 않는다. 기존 즉시 `GRIP_USE/GRIP_RELEASE`를 쓰는 작업공간은 그대로 동작하며, 설비에 연결된 매핑만 개폐 완료 조건을 따르도록 한다.

진공 그리퍼는 후속으로 흡착 ON/OFF, 흡착 영역, 응답 지연, 물체 유무 피드백을 추가한다. 손가락 애니메이션이 없는 경우에도 같은 소유권·I/O 경로를 사용한다.

## 6. I/O와 프로그램 연동

기본 흐름은 `로봇 프로그램 OUT → 설비 명령 → 위치 변화 → 센서 IN → 프로그램 조건 대기 해제`다. 수동 시험과 자동 운전은 동일 명령 처리 경로를 사용한다.

| 예시 설비 | 제어 출력 예시 | 피드백 입력 예시 |
|---|---|---|
| 컨베이어 | 운전·역운전 | 물체 감지·끝단 도달 |
| 실린더 | 전진·후진 | 전진 완료·후진 완료 |
| 그리퍼 | 닫기·열기 | 닫힘 완료·열림 완료·파지 성공 |
| 외부 축 | 위치 명령·이동 시작 | 목표 도달·운전 중·오류 |

주소는 사용자가 지정한다. 초기 버전은 기존 지원 범위의 비트를 사용하고, 외부 축 위치는 수동 목표 또는 기존 E축 값으로 연결한다. 워드 위치 명령은 부호·배율·범위를 정의한 뒤 추가한다.

센서에 연결된 IN의 제어 주체는 시뮬레이션 센서 / 수동 입력 / 외부 입력 중 하나로 선택한다. 같은 주소의 다중 쓰기는 저장 전에 오류로 표시한다. 연결된 센서 IN을 수동으로 바꾸려면 시험용 강제 입력 모드로 전환하고 화면에 그 상태를 표시한다. 공유 I/O와 로봇별 제어 범위는 현재 버스 구조를 확인한 뒤 명시하며 주소가 자동으로 격리된다고 가정하지 않는다.

연속 신호는 레벨 상태로 평가하고 단발 명령은 에지로 평가한다. 매 스캔 반복되는 OUT 대입으로 전진 동작이 다시 시작되지 않아야 한다. I/O 매핑 실패를 성공 신호로 처리하지 않는다.

OLP에서는 기존 출력·대기 명령을 우선 사용한다. 설비 전용 명령을 추가하거나 프로젝트 생성 결과를 바꾸는 작업은 필요성이 확인된 뒤 별도 범위로 진행한다. 외부 컨트롤러 피드백은 실제 지원 프로토콜을 확인한 후 연결하고 로컬 IN 변경이 자동으로 외부 장치에 전달된다고 가정하지 않는다.

## 7. 충돌·편집·저장 정책

- 움직인 가동부와 공작물은 기존 충돌 갱신 경로에 등록한다. 설비가 움직이는 프레임에는 관련 경계 정보도 갱신한다.
- 실린더 본체와 로드, 그리퍼와 파지 물체처럼 의도된 접촉은 지정한 부품 쌍만 예외로 둔다. 주변 설비 전체를 충돌 검사에서 제외하지 않는다.
- 로컬 자동 실행에서 충돌 정지 옵션이 켜져 있으면 관련 설비와 로봇을 정지하고 원인을 표시한다. 외부 컨트롤러 관측 모드에서는 기존 정책에 맞춰 경고만 표시하고 외부 장치를 정지시켰다고 표현하지 않는다.
- 설비 삭제·가동부 삭제·복사·Undo/Redo 시 참조를 점검한다. 복사한 설비는 새 ID를 받고 I/O 연결은 비활성으로 시작하여 주소 중복을 막는다.
- `.inosim`에는 설비 정의, 초기 상태, 현재 자세, 물체 소유권을 저장한다. 불러올 때 현재 자세를 복원하되 운전은 정지 상태로 시작한다.
- 실행 시작 스냅샷과 런타임 핸들은 영구 설정과 분리한다. 기존 파일에 설비 필드가 없으면 빈 설비 목록으로 처리한다.
- 가동부 참조는 임시 Three.js UUID 대신 기존 영구 모델 ID와 저장 가능한 부품 ID를 사용한다. 부품 ID의 안정성을 먼저 검증하고 필요한 경우 확장한다.
- 없는 부품·중복 ID·부모 순환이 있으면 해당 설비를 비활성화하고 복구 오류를 표시한다. 임의 부품을 대신 움직이지 않는다.
- 자동 복구에는 설정 편집을 반영하되 매 프레임 위치 저장으로 IndexedDB 쓰기가 폭증하지 않게 한다.

아래 신규 모듈명은 제안이며 기존 구조에 맞춰 확정한다.

| 파일 | 역할 |
|---|---|
| 신규 `equipment-core.mjs` | 설비 정의 정규화·검증·참조 관리 |

| 신규 `equipment-runtime.mjs` | 공통 시간, 명령 처리, 설비 상태, 실행·정지·초기화 |
| 신규 `equipment-transfer-core.mjs` | 물체 소유권, 파지·해제·인계 |
| 신규 `equipment-sensor-core.mjs` | 감지 영역, 끝 위치 센서, 빠른 통과 판정 |
| 신규 `equipment-scene-adapter.mjs` | Three.js 가동부 변환, 부모 프레임 전환, 충돌 갱신 연결 |
| 신규 `equipment-ui.mjs` | 설비 설정·수동 시험·상태 표시 |

| 기존 `io-function-mapping-core.mjs` | 기존 매핑 호환과 설비 명령 연결 |
| 기존 `olp-runtime.mjs` 및 로봇 모션 경로 | 공통 시간·일시정지 연동이 필요한 범위 |
| 기존 `workspace-recovery-core.mjs` 및 저장·복구 경로 | 설비 정의·참조·복구 호환 |
| 기존 `index.html`, `style.css`, 언어 자료 | 설비 설정 UI와 번역 |
| `tests/fast`, `tests/ui` | 기구 계산·상태·공정·저장 회귀 검사 |

핵심 계산은 DOM·Three.js에 의존하지 않는 모듈로 분리한다. 초기부터 별도 물리 엔진이나 기존 시뮬레이터 전체 재작성을 요구하지 않는다.

## 9. 개발 순서와 단계별 완료 기준

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 0. 기준 확인 | 기존 파지·E축·I/O·저장 동작 재현, 부품 ID 조사 | 현재 기능의 기준 테스트와 확장 경계 확보 |
| 1. 공통 기반 + 실린더 | 설비 정의, 직선 기구, 시간, 수동 시험, 센서, 최소 저장 | 100mm 행정을 50mm/s로 이동하면 시뮬레이션 2초에 완료; 중간 반전·정지·재개 정상 |
| 2. 그리퍼 | 손가락 개폐, 기존 파지 연결, 소유권, 완료 피드백 | 닫기→파지→로봇 이동→열기→해제 후 위치와 소유권 정상 |
| 3. 컨베이어 | 직선 이송, 감지 영역, 끝단 정지, 파지 인계 | 여러 물체 이송 중 하나를 집어도 나머지 이송 정상; 회전 배치 정상 |
| 4. 외부 축 | 직선·회전 모듈, 탑재물, E축 연결 | 가동부·탑재물이 함께 이동; 로봇 이중 이동 없음; TCP·좌표계 정상 |
| 5. 통합 공정 | OLP/I/O 연동, 충돌, 초기화, 전체 저장·복구 | 대표 공정 연속 반복 및 저장 후 재실행 성공 |
| 6. 후속 확장 | 자동 이송 등록, 진공, 컨베이어 인계·트래킹 | 기능별 별도 요구사항·검증 기준 확정 후 진행 |

1단계부터 저장·초기화와 최소 I/O 연결을 구현한다. 화면 애니메이션만 먼저 만들고 공정 제어·저장 기능을 마지막에 붙이는 순서로 진행하지 않는다. 기간 산정은 0단계에서 CAD 부품 참조와 기존 시간 경로를 확인한 뒤 확정한다.

## 10. 검증 계획

단위 검사는 위치·회전 계산, 속도·행정 경계, 완료 센서, 반대 명령, I/O 충돌, 소유권, 저장 정규화를 대상으로 한다. 브라우저 검사는 실제 부품 선택과 World 변환, 설정 UI, 실행·정지·복구를 확인한다.

필수 시나리오:

1. 30/60/120 FPS 조건에서 같은 시뮬레이션 시간의 위치·센서 상태가 같다.
2. 일시정지와 백그라운드 전환 후 재개해도 순간 이동하지 않는다.
3. 회전 배치한 컨베이어·실린더가 지정한 로컬 방향으로 움직인다.
4. 컨베이어 위 물체를 잡으면 이송에서 빠지고 로봇을 따라간다. 다른 설비에 놓으면 정확히 한 소유자에게 인계된다.
5. 빈 그리퍼 닫힘은 파지 성공을 발생시키지 않는다. 잘못된 크기의 공작물은 파지 실패로 표시한다.
6. 실린더의 완료 센서가 위치와 일치하고 반전·동시 명령·범위 초과를 처리한다.
7. 외부 축 가동부와 탑재물이 움직여도 고정부는 유지된다. 기존 E축 작업공간 결과가 유지된다.
8. 로봇이 I/O 대기 중이어도 설비는 움직이고 완료 센서로 대기가 해제된다.
9. 의도된 접촉은 허용하고 주변 장애물 충돌은 감지한다. 충돌 검사를 건너뛴 프레임을 안전 확인으로 간주하지 않는다.
10. 저장·불러오기·자동 복구·복사·삭제·Undo/Redo 후 부품·소유권 참조가 일치한다.
11. 대표 공정을 초기 제안 100회 반복하여 위치 오차·중복 파지·물체 복제가 없는지 확인한다.
12. 초기 성능 시험 장면은 로봇 1대, 컨베이어 2대, 공작물 50개, 실린더 4개, 그리퍼 1개, 외부 축 1개로 한다. 대상 PC와 CAD 복잡도를 기록해 측정하고 결과를 보고 목표를 확정한다.

코드·UI·데이터 수정 후에는 저장소 지침에 따라 각 수정 묶음마다 `npm run test:fast`, 작업 완료 시 `npm run verify:full`을 실행한다. 프로젝트 생성기 또는 외부 C# 생성기를 변경하는 후속 범위가 생기면 해당 기준 결과 검증과 `npm run test:dotnet-generator`를 수행한다. 실패와 미검증 범위를 숨기지 않는다.

## 11. 구현 완료 판단과 버전 기록

초기 배포 범위는 단계 1~5로 제안한다. 네 종류의 설비가 수동·I/O 제어로 동작하고, 대표 공정이 반복 실행되며, 기존 로봇·파지·E축·작업공간 기능의 회귀 검사가 통과해야 완료로 판단한다.

버전 기록은 실제 배포한 사용자 변화만 기록한다. 예: `컨베이어, 실린더, 그리퍼, 외부 축 설비 동작을 I/O와 연동하여 시뮬레이션할 수 있습니다.` 개발 중 시행착오와 내부 모듈 변경은 기록하지 않는다. 계획서 작성 자체는 앱 기능 업데이트로 기록하지 않는다.

## 12. 구현 시작 시 확정할 항목

- 첫 시연에 사용할 실제 CAD와 고정·가동 부품 구성
- 외부 축의 첫 대상이 로봇 탑재 레일인지 회전 테이블인지, 사용할 E축 번호·단위
- 실린더의 단일·이중 신호 제어 방식과 초기 위치
- 그리퍼의 개구폭·공작물 크기·파지 기준
- 로컬 OLP를 첫 연동 대상으로 사용할지, 외부 컨트롤러 관측도 초기 범위에 포함할지

이 항목이 미정이어도 공통 기반과 기본 도형을 이용한 실린더 시연부터 시작할 수 있다. 초기 기본안은 직선 컨베이어, 직선 레일, 2신호 실린더, 평행 2지 그리퍼, 로컬 OLP 연동으로 한다.

## 13. 추가 범위: 필름 박리와 유연체 표현

### 13.1 목표와 단계

로봇 또는 박리 장치가 필름 끝을 잡아 당기면 제품에 붙어 있는 부분은 표면에 남고, 박리 경계가 진행하면서 벗겨진 부분이 곡선을 그리도록 한다. 고정된 CAD 모델의 이동만으로는 구현할 수 없으므로 필름 전용 변형 메시를 사용한다.

| 수준 | 표현 | 제안 범위 |
|---|---|---|
| 1. 곡선 기반 박리 | 박리선과 파지점을 연결하는 띠 형태; 길이 보존과 매끄러운 굽힘 | 평면 제품·직선 박리부터 시작하는 시연 버전 |
| 2. 유연체 기반 박리 | 길이·굽힘 제약, 중력, 감쇠, 제품 충돌에 따른 처짐·잔흔들림 | 실제처럼 보이는 표현의 목표 버전 |
| 3. 접착 물리 해석 | 접착력·박리력·재료 특성에 따른 박리 진행·파손 | 재료 실험값과 별도 검증이 필요한 후속 범위 |

곡선 기반만으로 흔들림과 주름까지 실제처럼 재현했다고 판단하지 않는다. 우선 1단계에서 로봇·I/O·박리 진행을 검증하고, 사용자가 요청한 자연스러운 표현은 2단계까지 개발하는 것으로 제안한다. 이 추가 범위는 기존 설비 단계 1~5의 완료 기준과 별도로 관리한다.

### 13.2 형상과 박리 상태

- 필름은 길이·폭·두께와 제품 표면 기준 좌표를 가지며 길이·폭 방향으로 분할한 메시로 만든다. 분할 수는 시연 성능을 측정하여 결정한다.
- 부착 구간, 박리 경계, 자유 구간, 파지 구간을 구분한다. 초기 대상은 평면 제품과 폭 방향의 직선 박리 경계다.
- 전체 재료 길이는 부착 길이와 자유 길이의 합으로 보존한다. 파지점을 이동시켰다는 이유로 필름을 임의로 늘리지 않는다.
- 곡선 방식은 자유 길이와 양 끝 위치를 만족하도록 곡률을 조정한다. 단순 베지어 제어점 보간만으로 길이 보존을 보장할 수 없으므로 곡선 길이를 계산하고 제약을 검증한다.
- 자유 길이보다 파지점까지의 거리가 크면 허용된 박리량을 늘리거나 명령 불가 상태를 표시한다. 그리퍼와 필름 끝이 분리되거나 필름이 무한히 늘어나는 방식으로 처리하지 않는다.
- 로봇 접근·파지·당김·완전 박리·배출 순서를 연결한다. 멈추면 박리선은 유지하고, 이미 벗겨진 부분이 자동으로 다시 붙지 않게 한다.
- 완전 박리된 필름은 그리퍼 소유의 유연체로 유지한다. 그리퍼 해제 후의 낙하와 배출은 유연체 런타임에서 처리하므로 기존 강체 물체의 World 위치 유지 정책과 구분한다.

### 13.3 자연스러운 굽힘과 움직임

2단계에서는 위치 기반 동역학 계열의 길이·굽힘 제약을 적용하는 방식을 후보로 한다. 이 계열은 천의 변형·굽힘과 충돌 제약에 사용되는 방법이며, 필름의 접착 박리 법칙은 별도로 설계해야 한다. 참고: [Position Based Dynamics 원 논문](https://www.cs.toronto.edu/~jacobson/seminar/mueller-et-al-2007.pdf).

파지 구간은 그리퍼 프레임에 고정하고 부착 구간은 제품 표면에 고정한다. 자유 구간에는 중력·감쇠·굽힘 강성을 적용한다. 얇은 필름과 뻣뻣한 보호 필름의 굽힘 차이는 조절 가능하게 하되 실제 재료 물성을 검증한 값으로 표현하지 않는다.

박리 경계에는 최소 굽힘 반경 또는 전환 구간을 설정하여 날카롭게 꺾이는 모양을 줄인다. 로봇 방향 변화에 따른 비틀림은 폭 방향 메시와 파지 프레임으로 처리한다. 느슨해졌을 때 처지고 정지 후 흔들림이 줄어드는 표현을 검증한다. 복잡한 주름·자기 충돌은 별도 성능·안정성 검증 후 확장한다.

제품 관통 방지는 우선 평면·단순 충돌 형상으로 구현한다. 현재 강체 충돌 검사가 변형 필름의 접촉 해결까지 제공한다고 가정하지 않는다. 매 프레임 CAD 전체 메시의 충돌 구조를 재생성하기보다 유연체용 충돌 경로를 마련한다.

앞뒤 면, 법선, 재질을 갱신하여 굽힘이 조명으로 드러나게 한다. 얇은 두께는 재질 또는 가장자리 표현으로 처리하고 반투명 렌더링의 정렬 문제를 확인한다. 초기 버전은 겹침 검증이 쉬운 불투명 또는 약한 반투명 재질로 시작한다.

### 13.4 제어·저장과 개발 순서

설정에는 제품·필름 ID, 표면 프레임, 치수, 초기 들뜬 탭 길이, 박리 방향, 파지 구간, 박리 진행 방식, 굽힘·감쇠 값, 완료 센서를 둔다. 초기 들뜬 탭을 제공하여 제품에 완전히 붙은 필름을 그리퍼가 바로 잡을 수 있다고 가정하지 않는다.

초기 진행 방식은 로봇 당김과 길이 제약에 따라 박리 경계를 이동시키는 기구학 방식이다. 별도 속도 명령을 사용하면 로봇 동작과 양 끝 거리 제약을 함께 확인한다. 실제 접착력에 따른 박리 속도·필요 힘 계산은 3단계까지 지원한다고 표현하지 않는다.

기존 설비 런타임의 시간·I/O·일시정지·초기화를 사용한다. 저장에는 설정·박리량·파지 참조를 포함한다. 유연체의 현재 형상까지 복원하려면 정점 위치와 필요한 동역학 상태의 저장 정책을 추가해야 하며, 재로딩 후 정지 상태로 복원한다.

권장 순서는 평면 필름 생성 → 곡선·길이 보존 → 그리퍼·로봇 연동 → 박리 진행·완료 센서 → 유연체 굽힘·처짐 → 충돌·저장·성능 검증이다. 신규 `film-peeling-core.mjs`와 필름 장면 어댑터를 제안하며 기존 강체 물체에 유연체 계산을 적용하지 않는다.

### 13.5 추가 완료 기준

1. 같은 로봇 경로·시뮬레이션 시간에서 박리량과 형상을 재현한다.
2. 부착 구간은 제품 표면을 유지하고 박리 경계에서 자유 구간으로 형상이 이어진다.
3. 길이 오차가 정의한 허용오차 이내이며 파지점 연결이 유지된다.
4. 90도·180도 박리 시연과 방향 전환에서 자연스러운 굽힘을 확인한다. 불가능한 경로에는 오류를 표시한다.
5. 정지·재개·초기화에서 필름 형상이 튀거나 박리량이 되돌아가지 않는다.
6. 자유 구간이 중력으로 처지고 잔흔들림이 감쇠하며 제품을 관통하지 않는다.
7. 완전 박리 감지 후에도 필름이 그리퍼를 따라가며 해제·배출 상태로 전환된다.
8. 저장·복구 후 박리량·형상·파지 관계가 설정한 복원 정책에 맞는다.

시각 검증에는 실제 공정의 참고 영상 또는 사용자가 확인한 시연을 기준으로 사용한다. 접착력·박리력의 정확도는 재료 모델과 실험 검증이 없는 초기 버전의 완료 기준에 포함하지 않는다.
