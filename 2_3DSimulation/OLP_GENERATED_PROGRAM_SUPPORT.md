검증 대상은 현재 웹 프로젝트 생성기가 출력하는 프로그램입니다. Tray, Stage, MCR, Vision, Trash, Peeling, Tool 종류와 비전 IO/소켓 옵션 등을 조합한 75개 설정에서 `.pro` 565개를 수집했습니다. 허용되는 설정의 출력 파일 956개는 변경 전과 동일합니다. 별도 C# 생성기의 과거 템플릿 전체나 임의의 펌웨어 명령 전체를 지원한다는 의미는 아닙니다.

비전 프로그램을 시험할 때는 OLP의 가상 소켓 패널에서 프로그램의 채널 번호를 선택하고 연결 상태와 응답 문자열을 설정합니다. 자동 응답을 켜면 Send에 지정한 문자열로 응답하며, 수동 수신도 가능합니다. 기본 상태에서는 카메라 성공 응답을 임의로 만들지 않습니다. 실제 카메라 TCP 연결을 대신하는 오프라인 시험 장치입니다.

Home[0]을 맞추려면 실제 컨트롤러와 같은 관절 위치를 Work Origin으로 등록하고 출력 번호를 지정합니다. 생성기의 `yRobot_home_sts` 라벨만으로 OUT[519]가 자동 설정되는 것은 아닙니다. 등록하지 않은 Home[0]은 기존 시뮬레이터 기본 자세를 사용하므로 컨트롤러 원점과 같다고 가정하면 안 됩니다.

속도는 프로그램의 Velset와 실제 입력 기능 매핑을 구분합니다. 일반 OLP 시작에서는 Velset Rate를 사용합니다. 매핑된 Remote IO Start로 시작한 세션은 Remote IO 자동 모드로 취급하며, FuncId 8296 입력 워드가 바뀔 때 유효한 1~100 값만 반영합니다. 라벨 이름에 speed가 있다는 이유로 속도를 덮어쓰지 않습니다.

문자열 변환, IO 형식, Offset, 정적 태스크 End 및 속도 입력 트리거 등은 원본 ARM 함수 실행 결과를 기준값으로 대조했습니다. 생성 프로그램 실행 검사와 실제 브라우저의 3D 이동 검사는 별도로 수행합니다. 파싱 성공만으로 펌웨어 전체와 동일하다고 판단하지 않습니다.

사이클 타임을 비교할 때는 기종·Tool 부하·원점·포인트·V/Acc/Dec/Ramp·분기·외부 IO 응답 순서를 먼저 맞춰야 합니다. Z[CP] 연속 경로와 FreePlan 전체, 서보 지연, 컨트롤러 실시간 태스크 스케줄링은 아직 완전히 이식하지 않았습니다. MovL 경로가 직선이어도 가감속 프로파일과 블렌딩의 모든 시간이 원본과 동일한 것은 아닙니다. GetTorque는 모델의 동역학으로 추정한 모터 정격 대비 백분율이며 실측 전류·토크 피드백이 아닙니다. 따라서 이번 지원 범위의 프로그램 실행과 제어기 전체의 시간·물리 응답 일치는 구분해서 검증해야 합니다.
