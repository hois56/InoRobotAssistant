# 3D 시뮬레이션 도형 생성 기능 개발 계획서

- 작성일: 2026-09-02
- 대상: `2_3DSimulation`
- 목적: 3D 시뮬레이션에서 기본 솔리드 도형을 생성하고, 치수·위치를 CAD와 유사한 방식으로 편집할 수 있도록 한다.

## 1. 개발 목표

하단 제어 도크에 `도형` 버튼을 추가하고, 사용자가 다음 네 가지 도형을 장면에 생성할 수 있도록 한다.

- 사각형: 이 계획에서는 3차원 솔리드인 직육면체로 정의한다.
- 원뿔형: 원형 바닥을 가진 원뿔로 정의한다.
- 원통형: 원형 단면을 가진 원통으로 정의한다.
- 구: 세 축의 치수가 같은 구로 정의한다.

생성된 도형은 기존 모델과 동일하게 모델 트리에서 선택·삭제·복사할 수 있어야 하며, 시뮬레이션 작업 저장·복구와 충돌 감지에도 포함되어야 한다.

### 완료 조건

1. 하단 `도형` 버튼에서 도형 패널을 열고 네 가지 형상을 선택할 수 있다.
2. X, Y, Z 입력값으로 도형을 생성할 수 있다.
3. 생성 이후에도 도형 패널의 수치 입력과 3D 치수 라벨을 통해 값을 변경할 수 있다.
4. 선택된 도형의 원점이 도형 하단 중심에 있고, 위치값·JOG·TransformControls가 이 원점을 기준으로 동작한다.
5. BASE JOG와 유사한 X/Y/Z 버튼·수치 입력·3D 이동 핸들이 도형에도 동작한다.
6. 도형이 모델 트리, Undo/Redo, 작업 복구, 복사·붙여넣기, 충돌 감지와 호환된다.
7. 한국어·영어·중국어·베트남어에서 새 UI 문구가 누락되지 않는다.

## 2. 현재 프로젝트 기준점

현재 구현을 유지하면서 다음 확장 지점을 사용한다.

| 영역 | 기존 구현 | 확장 방향 |
| --- | --- | --- |
| 하단 버튼 | `2_3DSimulation/index.html`의 `#panel-launcher` | `data-panel-toggle="shape-panel"` 버튼 추가 |
| 패널 관리 | `main.js`의 `PANEL_MINIMUM_SIZES`, `PANEL_IDS`, `togglePanelVisibility()` | 도형 패널을 일반 패널 스택·팝아웃·복원 흐름에 등록 |
| 모델 선택 | `selectSceneModel()`, 화면 Raycaster, 모델 트리 | primitive shape도 `state.models`의 루트 모델로 등록 |
| 모델 변환 | `THREE.TransformControls`, `applySelectedModelNumericTransform()` | 위치·회전은 재사용하고, 치수는 shape 전용 함수로 분리 |
| BASE JOG | `setupBaseJogTransformControls()`, `setBaseJogGizmoEnabled()` | 로봇은 기존 IK 경로를 유지하고, 도형은 직접 위치를 변경하는 target 경로 추가 |
| 장면 저장 | `serializeWorkspaceSceneModel()`, `serializeWorkspaceSnapshot()`, `restoreWorkspaceSnapshot()` | `kind: "primitive-shape"` 레코드와 복구 루틴 추가 |
| Undo/Redo | `captureSceneSnapshot()`, `applySceneSnapshot()` | 도형 형상·치수 메타데이터를 snapshot 비교·복구 대상에 추가 |
| 충돌 감지 | `MeshCollisionSystem`, `markSceneCollisionDirty()` | 생성·치수 변경 때 primitive의 BVH/변환 캐시를 갱신 |
| 다국어 | `Language/*/robot-3d-viewer.json`, `uiText()` | 도형 패널·상태·형상명·치수 오류 문구를 네 언어로 추가 |

현재 작업 트리에 있는 3D 시뮬레이션의 미커밋 변경은 별도 작업으로 간주하고 덮어쓰지 않는다. 구현 시에는 해당 변경이 반영된 최신 파일을 기준으로 병합한다.

## 3. 좌표와 치수 정책

시뮬레이션은 `Z`축이 위쪽인 좌표계를 사용한다. 도형 루트의 로컬 원점과 위치값은 다음 규칙으로 고정한다.

```text
도형 루트 원점 (0, 0, 0)
        └── X/Y 평면상의 하단 중심
             └── 도형 형상은 Z >= 0 방향으로 생성
```

- 위치 입력값은 도형 루트의 월드 위치이며 단위는 `mm`이다.
- 회전은 도형 루트에 적용하고, 회전 전 기준점은 항상 하단 중심이다.
- 형상 메시를 루트에 직접 만들지 않고 `THREE.Group` 루트 아래에 메시를 둔다.
- 메시 정점 또는 geometry를 Z 방향으로 이동해 루트 원점이 하단 중심이 되도록 한다.
- 도형 치수 변경 시 루트의 위치·회전은 유지한다.
- 음수, 0, `NaN`, 무한대는 허용하지 않는다. 최소값과 최대값은 공통 정규화 함수에서 관리한다.
- 내부 계산과 저장은 숫자로 하고, 화면 표시만 소수점 3자리까지 반올림한다.

### 도형별 X/Y/Z 의미

| 형상 | X | Y | Z | 입력 연동 |
| --- | --- | --- | --- | --- |
| 사각형(직육면체) | 폭 | 깊이 | 높이 | 세 축 독립 |
| 원통형 | X 방향 지름 | Y 방향 지름 | 높이 | 원형 유지: X와 Y를 동일 값으로 연동 |
| 원뿔형 | 바닥 X 방향 지름 | 바닥 Y 방향 지름 | 높이 | 원형 유지: X와 Y를 동일 값으로 연동 |
| 구 | 지름 | 지름 | 지름 | 구 유지: 한 축 변경 시 세 축을 동일 값으로 연동 |

원통과 원뿔은 실제 원형 형상을 유지하기 위해 X/Y를 같은 지름으로 처리한다. 구도 진짜 구를 유지하기 위해 X/Y/Z를 같은 지름으로 처리한다. 비대칭 원통·타원체·원뿔대는 이번 범위에 포함하지 않으며, 나중에 별도 형상 타입으로 확장한다.

## 4. 사용자 흐름

### 4.1 도형 생성

```text
하단 도형 버튼
    ↓
도형 패널 열기
    ↓
형상 선택 + X/Y/Z 입력
    ↓
생성 버튼
    ↓
월드 원점의 그리드 위에 도형 생성
    ↓
도형 선택 + 치수 핸들/위치 핸들 표시
```

- 첫 번째 도형은 `(0, 0, 0)`에 생성한다.
- 생성 직후 도형을 `state.models`와 장면에 등록하고 자동 선택한다.
- 여러 도형을 만들 때도 각 도형은 독립적인 루트·ID·치수 상태를 가진다.
- 생성 중에는 기존 로봇 모션을 중단하거나 변경하지 않는다. 모션 실행 중 생성 허용 여부는 현재 로봇 모델 추가·교체 정책과 충돌하지 않도록 `도형 생성은 정지 상태에서만 허용`으로 한다.
- 생성 실패 시 임시 geometry·material·이벤트 상태를 정리하고 기존 장면을 변경하지 않는다.

### 4.2 생성 이후 치수 변경

두 가지 입력 경로를 같은 적용 함수로 연결한다.

1. 도형 패널의 X/Y/Z 입력값을 수정한다.
2. 도형을 클릭해 선택한 뒤 3D 화면에 표시되는 X/Y/Z 치수값을 클릭한다.

치수 라벨 입력은 다음 동작을 지원한다.

- 클릭: 해당 축의 숫자 입력으로 전환
- `Enter`: 값 적용
- `Escape`: 기존 값으로 취소
- 포커스 아웃: 유효한 값이면 적용하고, 잘못된 값이면 기존 값으로 복원
- 적용 전후 geometry 크기와 충돌 상태를 갱신

### 4.3 위치 이동

- 도형을 클릭하거나 모델 트리에서 선택하면 선택 상태를 만든다.
- 기존 모델 TransformControls의 이동·회전 핸들을 사용할 수 있다.
- JOG 패널을 열면 로봇이 선택된 경우에는 기존 BASE JOG가 표시되고, primitive shape가 선택된 경우에는 `SHAPE POSITION / BASE`가 표시된다.
- 도형 JOG의 X/Y/Z 수치 입력, `+/-` 버튼, 마우스로 끄는 3D 조이스틱은 모두 도형 루트의 position을 직접 변경한다.
- 도형에는 로봇 IK를 적용하지 않는다. 이동 중 간섭이 발생하면 기존 충돌 상태 표시를 사용한다.

### 5.1 하단 도형 버튼

`#panel-launcher`에 다음 버튼을 추가한다.

```html
<button id="btn-shape-panel"
        type="button"
        data-panel-toggle="shape-panel"
        title="도형 패널 표시/숨김"
        aria-label="도형 패널 표시/숨김">
    <i class="fa-solid fa-cubes-stacked" aria-hidden="true"></i>
    도형
</button>
```

- 로봇이 없어도 활성화한다.
- 버튼 활성 상태는 기존 패널 런처와 동일하게 처리한다.
- 모바일에서는 기존 하단 도크의 아이콘 중심 레이아웃을 따른다.
- 언어 전환 시 버튼 텍스트·title·aria-label을 함께 갱신한다.

### 5.2 도형 패널

`#canvas-container` 안에 `aside#shape-panel`을 추가한다. 기존 패널의 이동·크기 조절·별도 창 분리 규칙을 재사용한다.

#### 새 도형 영역

- 형상 선택: 사각형, 원뿔형, 원통형, 구
- X, Y, Z 입력: `mm`
- 원형 형상 안내: `X/Y 지름은 함께 변경됩니다.`
- 구 안내: `X/Y/Z 지름은 함께 변경됩니다.`
- 생성 버튼
- 입력 오류 영역: `role="alert"`

#### 선택 도형 영역

도형을 선택하면 같은 패널에 다음을 표시한다.

- 선택 도형명과 도형 타입
- 현재 X/Y/Z 치수
- 연결 축 표시 및 잠금 상태
- 현재 위치 X/Y/Z는 기존 모델 변환 패널과 중복하지 않고 JOG 또는 모델 변환 패널에서 편집
- 선택 해제 또는 일반 모델 선택 시 선택 도형 편집 영역 숨김

### 5.3 모델 트리

`getModelTreeMeta()`에 primitive shape 분기를 추가한다.

- 종류: `도형`
- 아이콘: `fa-cubes-stacked`
- 이름: `사각형 1`, `원통형 1`처럼 중복되지 않는 기본 이름
- 선택, 우클릭 삭제, 복사·붙여넣기, 표시/숨김을 기존 모델과 동일하게 지원

도형 하위에는 CAD 파츠 목록을 만들지 않는다. 대신 하나의 루트가 형상·재질·치수 메타데이터를 소유한다.

## 6. 장면 데이터 및 geometry 설계

### 6.1 루트 객체 메타데이터

primitive shape의 루트 `THREE.Group`에는 다음 `userData`를 둔다.

```js
{
    primitiveShape: true,
    primitiveShapeType: 'box' | 'cone' | 'cylinder' | 'sphere',
    primitiveShapeDimensions: { x: 100, y: 100, z: 100 },
    primitiveShapeDimensionUnit: 'mm',
    primitiveShapeSchemaVersion: 1,
    modelName: '사각형 1',
    workspaceModelId: 'model-...',
    modelTreeId: 'scene-model-...',
    placement: 'scene',
    collisionEnabled: true
}
```

렌더링 중 생성되는 geometry, dimension line, HTML 입력 요소, 선택 강조선은 저장 메타데이터에 직접 넣지 않는다. 저장 가능한 값과 런타임 객체 참조를 분리한다.

### 6.2 geometry 생성 규칙

Three.js 기본 geometry는 중심이 원점인 경우가 많으므로, 공통 빌더에서 생성 직후 하단 중심 기준으로 이동한다.

- 직육면체: `BoxGeometry(x, y, z)` 후 geometry를 `Z = z / 2`만큼 이동
- 원통: `CylinderGeometry(radius, radius, z, radialSegments)` 후 `Z = z / 2`만큼 이동하고 루트 기준 Z축 방향으로 배치
- 원뿔: `ConeGeometry(radius, z, radialSegments)` 후 `Z = z / 2`만큼 이동하고 루트 기준 Z축 방향으로 배치
- 구: `SphereGeometry(diameter / 2, widthSegments, heightSegments)` 후 중심을 `Z = diameter / 2`로 이동

실제 구현에서는 프로젝트의 Z-up 좌표계와 Three.js geometry 기본 up 방향을 확인한 뒤, 메시 회전 또는 정점 이동 중 하나만 사용한다. 같은 보정을 중복 적용하지 않도록 geometry 테스트에서 하단 최소 Z가 0인지 검사한다.

### 6.3 치수 정규화 모듈

큰 `main.js`에 검증 로직을 모두 넣지 않도록 순수 함수 모듈을 추가한다.

- 권장 파일: `2_3DSimulation/primitive-shape-core.mjs`
- 역할:
  - 지원 형상 목록과 기본값
  - 최소·최대 치수 정규화
  - 형상별 X/Y/Z 연동
  - 저장 데이터 마이그레이션
  - 치수 표시 이름과 단위 메타데이터
  - geometry 생성에 필요한 반지름·높이 계산

Three.js 객체 생성과 DOM 조작은 `main.js`에 두고, 위 모듈은 Node 검증 스크립트에서 직접 테스트할 수 있게 한다.

## 7. 치수 표시 및 편집 설계

### 7.1 화면 표시 구조

선택된 primitive shape에만 CAD 스타일 오버레이를 표시한다.

- 3D 선: `THREE.Line` 또는 동일 목적의 선 geometry
- 화살표: `THREE.ArrowHelper` 또는 재사용 가능한 선·삼각형 화살표 메시
- 값 라벨: `#canvas-container` 안의 HTML overlay
- 라벨 위치: 해당 축의 양 끝점을 카메라에 투영한 중간점
- 선·화살표: 항상 확인 가능하도록 선택 전용 render order와 depth 설정 사용
- 마우스 이벤트: 라벨 입력만 받으며, 나머지 선은 장면 선택을 가로막지 않음

축별 기본 표현은 다음과 같다.

| 축 | 표시 위치 | 라벨 |
| --- | --- | --- |
| X | 도형 좌우 끝점 바깥쪽 | `X = ... mm` |
| Y | 도형 앞뒤 끝점 바깥쪽 | `Y = ... mm` |
| Z | 도형 하단과 상단 사이 | `Z = ... mm` |

원통·원뿔은 X/Y를 지름으로 표시하고, 구는 X/Y/Z 라벨을 동일 값으로 표시하되 하나를 편집하면 모두 함께 갱신한다. 투영된 라벨이 화면 밖으로 나가면 오프셋을 줄이고, 서로 겹치면 축별 고정 오프셋을 순차 적용한다.

### 7.2 오버레이 수명주기

- 도형 선택: 오버레이 생성 또는 기존 오버레이의 대상 변경
- 도형 치수·위치·회전 변경: 끝점과 라벨을 즉시 재계산
- 카메라 이동·회전·줌: 다음 render frame에서 화면 위치 갱신
- 창 크기 변경: `onResize()` 후 즉시 재투영
- 선택 해제·도형 숨김·패널 종료: 오버레이와 입력 요소 숨김
- 도형 삭제·장면 초기화: 선 geometry, 재질, DOM 요소까지 해제

### 7.3 편집 충돌 방지

치수 라벨을 편집하는 동안에는 다음 이벤트를 일시적으로 막는다.

- 모델 선택 Raycaster
- OrbitControls의 화면 회전·이동
- TransformControls의 드래그
- 도형 JOG 버튼의 반복 입력

입력 완료 후 하나의 history transaction만 생성한다. `input` 이벤트마다 Undo 항목을 만들지 않고, focus 시작 시 before snapshot을 만들고 Enter·blur 시 after snapshot을 기록한다.

## 8. JOG 및 TransformControls 통합

### 8.1 JOG 대상 추상화

현재 BASE JOG는 로봇 TCP를 IK로 계산한다. 도형까지 로봇 로직에 넣지 않고, JOG 대상만 분리한다.

```js
state.baseJogTarget = {
    kind: 'robot' | 'primitive-shape',
    object: robotOrShape,
    position: THREE.Vector3,
    quaternion: THREE.Quaternion
}
```

- `kind: robot`: 기존 `solveRobotIK()`·TCP 표시·관절 동기화 경로 사용
- `kind: primitive-shape`: 선택 도형 루트의 position·quaternion을 직접 변경
- target 변경 시 기존 gizmo를 detach한 뒤 새 target에 attach
- 도형 target에는 IK 제한을 적용하지 않지만, 숫자 범위·모션 실행 중 잠금·충돌 갱신은 적용

### 8.2 도형 조이스틱

기존 `baseJogTransformControls`를 무조건 로봇만 가리키도록 두지 말고, 다음 중 한 가지로 확장한다.

1. `baseJogTransformControls`의 이벤트는 유지하고 target resolver만 로봇/도형으로 분기한다.
2. 로봇용과 도형용 `TransformControls`를 별도로 만들고 공통된 enable·detach·history 함수를 사용한다.

권장안은 2번이다. 로봇의 IK 프록시와 도형 루트의 직접 이동 객체가 서로 상태를 오염시키지 않기 때문이다.

도형 JOG 조이스틱의 동작은 다음과 같다.

- 이동 모드: X/Y/Z 축 핸들로 도형 루트를 이동
- 회전 모드: 기존 BASE JOG와 같은 RZ/RY/RX 축 순서를 사용
- Space 임시 전환: 현재 구현처럼 이동 핸들을 회전 핸들로 잠시 전환
- 드래그 시작: before snapshot 저장
- 드래그 중: 루트 transform 적용, collision dirty 표시, 위치 수치 동기화
- 드래그 종료: after snapshot 기록

### 8.3 기존 모델 변환과의 충돌 방지

primitive shape에서 기존 `scale` TransformControls를 그대로 허용하면 `userData.primitiveShapeDimensions`와 실제 mesh가 달라질 수 있다. 따라서 다음 정책을 사용한다.

- primitive shape는 TransformControls에서 이동·회전만 사용
- 치수 변경은 도형 패널 또는 CAD 치수 라벨에서만 처리
- 기존 모델의 일반 scale 모드는 imported/catalog 모델에만 유지
- 필요하면 선택 도형 패널에 `치수` 상태를 별도로 표시하고 기존 `크기` 버튼은 비활성화

## 9. 기록·복구·복사·삭제 연동

### 9.1 Undo/Redo

다음 작업은 각각 하나의 기록으로 남긴다.

- 도형 생성
- 도형 삭제
- 도형 치수 변경
- 도형 위치·회전 변경
- 도형 JOG 드래그 완료
- 도형 복사·붙여넣기

`captureSceneSnapshot()`에 primitive shape의 다음 값을 추가한다.

- 형상 타입
- 정규화된 X/Y/Z 치수
- material 색상 등 유지가 필요한 표시값
- 루트 position, quaternion, scale
- visible 상태

`applySceneSnapshot()`에서는 snapshot과 현재 geometry 메타데이터가 다르면 기존 mesh를 dispose하고 동일 루트에 새 geometry를 만든다. 루트 참조·workspace ID·선택 상태는 유지한다.

### 9.2 작업 저장 및 복구

`serializeWorkspaceSceneModel()`의 반환 타입을 확장한다.

```js
{
    kind: 'primitive-shape',
    workspaceModelId: 'model-...',
    name: '원통형 1',
    primitiveShapeType: 'cylinder',
    primitiveShapeDimensions: { x, y, z },
    transform: { position, quaternion, scale },
    visible: true,
    materialColor: '#bfc7d5'
}
```

- 기존 `uploaded`·`catalog` 레코드는 변경하지 않는다.
- `restoreWorkspaceSnapshot()`에서 primitive 레코드를 별도 루틴으로 먼저 복구한다.
- 기존 저장 데이터에 primitive 필드가 없으면 지금과 동일하게 catalog/imported model로 복구한다.
- 새 필드는 선택적 필드로 읽어 구버전 작업을 깨뜨리지 않는다.
- 복구 완료 후 `state.models`, 모델 트리, 선택 도형, 치수 오버레이, 충돌 캐시를 순서대로 갱신한다.
- `workspaceSnapshotHasWork()`가 primitive shape만 있는 작업도 작업 있음으로 판단하는지 확인한다.

### 9.3 복사·붙여넣기 및 삭제

- clipboard snapshot에 `primitiveShapeType`와 `primitiveShapeDimensions`를 포함한다.
- 붙여넣을 때 geometry를 새로 생성하고 새 workspace/model tree ID를 발급한다.
- 기존 붙여넣기 오프셋 정책을 따르되, 도형의 원점은 항상 하단 중심으로 유지한다.
- 삭제 시 dimension overlay, JOG target, collision debug overlay, geometry, material을 모두 정리한다.
- 도형을 호스트로 사용하는 attachment는 현재 범위에 포함하지 않는다. 향후 부착 기능을 추가할 때 별도의 attachment frame 정책을 정의한다.

## 10. 충돌 감지 연동

도형은 장면 충돌 대상 모델로 취급한다.

- 생성 직후 `state.models.push()`와 `state.scene.add()`를 수행한 뒤, 충돌 감지가 켜져 있으면 `system.prepare([shape])`를 호출한다.
- 치수 변경 전 기존 충돌 cache와 geometry를 정리하고 새 geometry를 준비한다.
- 위치·회전·JOG 이동 중에는 `markSceneCollisionDirty(shape)`를 호출한다.
- 변경 완료 후 기존 `checkSceneCollisions()`의 주기·강제 검사 정책을 따른다.
- dimension line, arrow, label, selection outline은 collision 대상에서 제외한다.
- 충돌 감지가 꺼진 새 시뮬레이션의 현재 기본 정책은 유지한다.

원뿔·원통·구의 원형 세그먼트 수는 렌더링 품질과 충돌 비용을 함께 고려한다. 기본값은 중간 수준으로 두고, primitive는 CAD 대용량 파일처럼 고해상도 메시를 생성하지 않는다. 필요하면 충돌 geometry만 더 낮은 세그먼트로 분리한다.

## 13. 검증 계획

### 13.1 자동 검증

새 검증 스크립트 `tools/validate-primitive-shapes.mjs`에서 다음을 검사한다.

- 네 형상 타입만 허용되는지
- X/Y/Z가 빈 값·음수·0·비정상 숫자를 거부하는지
- 원통·원뿔은 X/Y가 동기화되는지
- 구는 X/Y/Z가 동기화되는지
- 네 geometry의 하단 최소 Z가 0이고 중심 X/Y가 0인지
- 저장 레코드의 `kind`, 타입, 치수, transform이 복구 입력으로 충분한지
- 기존 catalog/imported 저장 형식이 변경되지 않았는지
- HTML에 `shape-panel`, `btn-shape-panel`, 치수 입력과 접근성 속성이 존재하는지
- CSS에 패널·치수 라벨·모바일 규칙이 존재하는지

기존 검증도 다시 실행한다.

```powershell
node tools/validate-primitive-shapes.mjs
node tools/validate-collision-system.mjs
node tools/validate-workspace-recovery.mjs
node tools/validate-3d-simulation-snaps.mjs
node tools/validate-motion-program.mjs
node tools/validate-localized-site.cjs
```

구문 검사도 수행한다.

```powershell
node --check 2_3DSimulation/main.js
node --check 2_3DSimulation/primitive-shape-core.mjs
```

| --- | --- |
| 기존 geometry가 Y-up 기준일 가능성 | `setupScene()`의 Z-up 설정과 실제 geometry 경계를 테스트로 확인하고 보정은 한 곳에서만 수행 |
| 원통·원뿔의 X/Y 요구와 원형 형상 충돌 | X/Y를 지름으로 정의하고 자동 연동하며, UI에 잠금 안내 표시 |
| 구의 세 축 독립 변경으로 타원체가 되는 문제 | 세 축을 같은 지름으로 저장하고 하나의 편집이 세 값에 반영되도록 제한 |
| 기존 generic scale과 shape dimensions 불일치 | primitive에서 scale 모드를 잠그고 전용 치수 적용 함수만 허용 |
| 카메라 이동 중 HTML 라벨이 어긋남 | render loop에서 모델 월드 행렬 업데이트 후 투영하고, 연속 렌더 조건에 overlay 활성 상태를 포함 |
| 치수 변경 후 stale collision cache | geometry 교체 전후 `markSceneCollisionDirty()`와 필요 시 `system.prepare()` 호출 |
| 복구 중 geometry 참조 누락 | 저장에는 geometry를 넣지 않고 타입·치수만 저장한 뒤 복구 시 새로 생성 |
| 기존 작업 복구 회귀 | primitive 필드가 없는 구버전 레코드 경로를 별도 회귀 테스트로 고정 |
| 패널이 많아 하단 도크가 좁아짐 | 기존 모바일 아이콘 레이아웃, 런처 그룹·스크롤 규칙을 재사용하고 도형 버튼은 항상 접근 가능하게 배치 |

## 15. 최종 산출물

- 동작하는 3D primitive shape 생성·편집 기능

- primitive shape 자동 검증 스크립트
- 네 언어 번역 및 생성 산출물
