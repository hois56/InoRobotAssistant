# 2D 스케치 모드 및 CAD 가져오기 전면 개편 계획서

- 작성일: 2026-09-07
- 대상: `2_3DSimulation`
- 목적: 현재의 임시적인 `2D 모드`와 장면 배치용 `2D CAD` 기능을, SolidWorks·Fusion의 스케치 작업 흐름에 가까운 하나의 스케치 작업공간으로 재설계한다.
- 1차 공식 파일 지원: `DXF`만 지원한다. `DWG`는 별도 변환 브리지가 필요하므로 이번 범위에서 제외하고, 지원 파일 목록·가져오기 UI·검증 대상에 포함하지 않는다.
- 범위: 구조 분석과 구현 계획. 이 문서 작성 단계에서는 제품 동작을 변경하지 않는다.

## 1. 결론

현재 기능을 부분적으로 보수하는 것보다 `Sketch Workspace`를 새로 정의하고, 기존 기능을 그 안으로 이전하는 편이 안전하다.

핵심 방향은 다음과 같다.

1. 별도의 `스케치 모드` 버튼을 추가하고, 기존 `도형 생성` 버튼과 기능·진입 경로를 분리한다.
2. 스케치 모드는 단순히 사각형·원·선을 드래그해 3D 도형을 만드는 화면이 아니라, 독립적인 `스케치 문서`를 편집하는 작업공간으로 만든다.
3. DXF는 3D 장면에 별도 모델로 덧붙이는 방식이 아니라, 스케치 요소 또는 참조 도면으로 가져온다. DWG는 이번 범위에서 제외한다.
4. 스케치와 돌출·컷을 분리한다. `Finish Sketch`는 스케치를 닫는 동작이고, 돌출·컷은 그 스케치를 참조하는 후속 피처가 된다.
5. 기존 3D 모델 가져오기와 프로젝트 복구는 유지하되, 스케치 관련 상태·형상·구속조건을 별도 스키마로 저장한다.
6. 기존 기능을 한 번에 삭제하지 않고 호환 어댑터를 둔 뒤, 새 스케치 흐름이 안정화되면 기존 경로를 제거한다.

## 2. 현재 구현 분석

### 2.1 현재 구조

| 영역 | 현재 구현 | 문제의 본질 |
|---|---|---|
| 2D 모드 | `state.sketch`에 선·사각형·원·모따기를 담고 드래그 후 즉시 돌출 또는 컷 | 스케치 문서가 아니라 일회성 도형 생성 대화상자에 가깝다. |
| CAD 가져오기 | `state.cad2d`에 CAD 문서와 Three.js 루트를 보관하고 장면에 `2D CAD` 모델로 추가 | CAD가 스케치 편집 대상이 아니라 별도 장면 모델로 취급된다. |
| CAD 선택 | 선·면 선택, 레이어 표시, 기준점 배치, 프로파일 돌출 | 선택한 원본 엔티티를 스케치 엔티티로 변환해 계속 편집하는 흐름이 없다. |
| 파일 가져오기 UI | 공통 `3D/CAD 파일 가져오기` 창에서 3D와 DXF를 함께 처리 | 사용자가 “스케치 안에 도면 삽입”하려는 의도와 UI가 맞지 않는다. DWG는 별도 브리지 문제로 공식 지원 대상이 아니다. |
| 저장·복구 | CAD 원본 파일과 완료된 돌출 모델은 저장 가능 | 작업 중인 스케치, 구속조건, 선택 상태, 편집 가능한 원본 스케치가 저장되지 않는다. |
| 구현 집중도 | `main.js` 약 33,633줄에 3D 장면·CAD·스케치·복구·UI 이벤트가 함께 존재 | 기능을 추가할수록 상태 전이가 서로 얽히고 회귀 범위가 커진다. |

근거가 되는 주요 경로:

- `main.js`의 `state.sketch`와 `state.cad2d`는 별도 상태로 정의되어 있다.
- `enterSketchMode()`는 진입할 때마다 엔티티를 비우고 기본 도구를 사각형으로 되돌린다.
- `handleSketchPointerDown/Move/Up()`는 빈 평면에서 드래그해 새 요소를 만드는 동작에 집중한다.
- `finishSketchAndCreateShape()`는 스케치를 별도 피처로 남기기보다 즉시 돌출 형상을 생성하거나 컷을 적용한다.
- `handleCad2DImport()`는 CAD 문서를 Three.js 장면 루트로 추가하고 `cad-2d` 모델로 저장한다.
- `restoreWorkspaceCad2d()`는 CAD 장면 모델을 다시 만들며, `restoreWorkspaceSketchFeature()`도 완료된 돌출 형상만 복원한다.

### 2.2 사용자가 체감하는 주요 문제

#### A. 버튼과 모드의 경계가 불명확하다

- 현재 스케치 진입 버튼이 도형 생성 영역에 종속되어 있어, 스케치 편집과 기본 도형 생성이 구분되지 않는다.
- `도형 생성` 버튼은 박스·원통·구 등의 기본 3D 도형 생성만 담당해야 한다.
- 별도의 `스케치 모드` 버튼은 메인 작업공간에서 독립적으로 제공하고, 평면 선택과 스케치 문서 편집을 시작해야 한다.
- 스케치 진입 시 기존 스케치 문서를 열거나 새 스케치를 선택할 수 없다.
- XY 평면에만 사실상 종속되어 있고, 특정 3D 면을 선택해 그 면에 스케치하는 흐름이 없다.
- 종료·취소·돌출이 하나의 패널에 섞여 있어 스케치 편집과 3D 피처 생성의 경계가 불명확하다.

#### B. 기존 요소를 편집할 수 없다

- 마우스 드래그는 새 요소 생성에 사용되고, 기존 선·원·프로파일을 선택해 이동하거나 꼭짓점을 수정하는 편집 모델이 없다.
- 선택 엔티티는 사실상 마지막 또는 현재 엔티티 중심이며 다중 선택·창 선택·선택 필터가 없다.
- 치수 표시는 지속적인 구속조건이 아니라 선택된 요소의 값을 직접 바꾸는 UI에 가깝다.
- 요소 간 일치, 수평·수직, 평행·직각, 접선, 동심, 동일 길이 같은 관계가 없다.

#### C. 스케치 도구가 CAD 작업 흐름에 부족하다

현재 도구는 `line`, `rectangle`, `circle`, `chamfer` 중심이다. 다음이 빠져 있다.

- 호, 3점 호, 타원, 폴리라인, 중심선·구성선
- 끝점·중점·중심·교차점·그리드·기존 요소에 대한 스냅
- trim, extend, split, fillet, offset, mirror, pattern
- 프로파일 자동 폐합 및 교차·자가 교차 오류 안내
- 스케치 원점·축·기준선과의 구속
- 완전 구속/미구속 상태와 남은 자유도 표시

#### D. CAD 가져오기가 스케치에 연결되지 않는다

- DXF·DWG를 가져오면 장면에 별도 CAD 루트가 추가된다.
- 선을 선택한 뒤 프로파일을 돌출할 수는 있지만, 가져온 선을 스케치 도구로 수정하거나 구속할 수 없다.
- CAD 패널은 레이어·가시성·기준점·돌출 기능이 한곳에 섞여 있다.
- 가져오기 위치 중심화, CAD 원점 오프셋, 모델 transform이 스케치 좌표계와 분리되어 관리된다.

#### E. DXF 파일 지원과 품질이 스케치 목적에 비해 약하다

- 브라우저 DXF 파서는 ASCII DXF 중심이며 Binary DXF는 거부한다.
- 스플라인은 새 스케치 변환 대상에서 제외하고, 발견 시 지원하지 않는 엔티티로 명시한다. `RAY/XLINE`도 스케치 형상으로 변환하지 않는다.
- DXF 파서가 지원하지 않는 엔티티는 경고 후 생략하지만, 사용자에게 “스케치로 변환 가능한 요소”와 “참조로만 남은 요소”를 구분해 주지 않는다.
- DWG는 별도 변환 브리지가 필요하므로 이번 릴리스에서는 파일 확장자·가져오기 UI·변환 API 모두 공식 지원 범위에서 제외한다.
- 블록/삽입, 문자·치수·해치 등 도면 표시용 요소와 실제 스케치 형상을 구분하는 정책이 없다.

#### F. 저장·복구·히스토리의 단위가 맞지 않는다

- 완료된 돌출 결과는 저장되지만, 돌출 전의 편집 가능한 스케치 작업은 별도 객체로 저장되지 않는다.
- CAD 원본은 복구되지만 CAD 장면 모델로 복구된다.
- 스케치 편집 중 브라우저가 종료되면 현재 요소·구속조건·뷰·작업 평면을 그대로 이어서 편집할 수 없다.
- `main.js`의 전역 이벤트와 장면 상태에 의존하므로 undo/redo를 스케치 명령 단위로 확장하기 어렵다.

### 2.3 현재 검증의 한계

현재 검증 스크립트는 통과한다. 다만 검증 내용은 ASCII DXF 파싱, 프로파일 영역 생성, 기존 포인터 이벤트와 CAD 뷰 제어 등 현재 기능의 내부 동작에 집중되어 있다.

아직 검증되지 않은 핵심 요구는 다음과 같다.

- 스케치 평면 선택과 평면 좌표계 전환
- 기존 스케치 요소 선택·이동·꼭짓점 편집
- CAD를 편집 가능한 스케치 요소로 변환
- 구속조건과 치수의 지속성·재계산
- 스케치 수정 후 기존 돌출 피처의 재생성
- 작업 중 스케치의 저장·복구
- 실제 브라우저에서 대용량 도면을 조작하는 성능

## 3. 목표 사용자 흐름

1. 사용자가 기존 도형 생성 버튼과 분리된 `스케치 모드` 버튼을 누른다.
2. `XY`, `YZ`, `ZX` 평면 또는 기존 3D 모델의 면을 선택한다.
3. 카메라가 해당 평면에 수직으로 정렬되고, 스케치 전용 그리드·원점·축이 표시된다.
4. 스케치 도구로 요소를 만들고, 요소를 선택·이동·수정·삭제한다.
5. DXF를 `CAD 삽입`으로 가져온다.
   - 기본값: 편집 가능한 스케치 요소로 변환
   - 선택 옵션: 참조 도면으로만 유지, 원본 레이어 유지, 구성선으로 가져오기
   - DWG: 공식 지원하지 않으며 파일 선택 대상에서도 제외
6. 끝점·중점·중심·교차점·그리드에 스냅하고, 필요한 치수와 구속조건을 추가한다.
7. 프로파일 오류, 열린 체인, 중복 선, 자가 교차를 즉시 확인한다.
8. `스케치 완료`를 누르면 스케치가 저장되고 편집 모드가 종료된다.
9. 이후 `돌출`, `돌출 컷` 같은 3D 피처가 해당 스케치를 참조한다.
10. 나중에 피처 트리에서 스케치를 다시 열어 수정하면 연결된 피처가 재생성된다.

## 4. 목표 데이터 모델

### 4.1 SketchDocument

```js
{
  schemaVersion: 1,
  id: 'sketch-...',
  name: 'Sketch 1',
  plane: {
    type: 'world-xy' | 'world-yz' | 'world-zx' | 'model-face',
    origin: [0, 0, 0],
    xAxis: [1, 0, 0],
    yAxis: [0, 1, 0],
    normal: [0, 0, 1],
    hostModelId: null,
    hostFaceId: null
  },
  unit: 'millimeter',
  entities: [],
  constraints: [],
  dimensions: [],
  importSources: [],
  settings: { gridVisible: true, snapEnabled: true }
}
```

엔티티는 화면용 샘플 점만 저장하지 않고, 가능한 경우 원본의 해석적 형상을 보존한다.

```js
{
  id: 'entity-...',
  type: 'line' | 'arc' | 'circle' | 'ellipse' | 'polyline',
  construction: false,
  geometry: { /* 엔티티 종류별 원본 좌표 */ },
  sourceRef: { documentId, handle, layerId, importIndex }
}
```

### 4.2 CAD 변환 정책

DXF 파서는 `CAD2D IR`을 반환하고, 그 다음 단계에서 `SketchEntity`로 변환한다. DWG 변환 브리지와 DWG 입력 경로는 이번 계획에 포함하지 않는다.

- `LINE`, `ARC`, `CIRCLE`, `ELLIPSE`, `LWPOLYLINE`, `POLYLINE`: 가능한 경우 편집 요소로 변환
- `POINT`, 중심선, 보조선: 구성선 또는 참조 요소로 변환
- `SPLINE`, `TEXT`, `DIMENSION`, `HATCH`, 미지원 블록: 스케치 형상으로 변환하지 않고 명확한 경고와 함께 제외
- 단위·레이어·원본 handle·변환 경고를 `sourceRef`와 `importSources`에 보존

## 5. 목표 코드 구조

현재처럼 모든 동작을 `main.js`에 계속 추가하지 않고, 다음 경계를 만든다.

| 모듈 | 책임 |
|---|---|
| `sketch-core.mjs` | 문서 스키마, 생성·복제·정규화·마이그레이션 |
| `sketch-geometry.mjs` | 엔티티 생성, 좌표 변환, bounds, 폐합·교차·프로파일 판정 |
| `sketch-constraints.mjs` | 구속조건 저장, 검증, 단계적 solve 및 잔여 자유도 계산 |
| `sketch-commands.mjs` | 생성·삭제·이동·trim·치수 변경을 명령으로 만들고 undo/redo 처리 |
| `sketch-viewport.mjs` | 평면 카메라, 그리드, 축, 화면 좌표와 스케치 좌표 변환 |
| `sketch-renderer.mjs` | 스케치 엔티티, 선택 상태, 스냅 마커, 구속조건 표시 |
| `cad-to-sketch.mjs` | CAD2D IR을 SketchEntity/참조 요소로 변환 |
| `sketch-feature.mjs` | 스케치 참조 기반 돌출·컷 피처와 재생성 |
| `main.js` | 기존 장면·로봇과 새 스케치 모듈을 연결하는 얇은 orchestration 계층 |

Three.js 렌더러는 재사용하되, 스케치 모드에서는 독립적인 직교 카메라·평면 좌표계·선택 레이어를 사용한다. 스케치 진입 전 카메라를 저장했다가 복원하는 현재 방식을 확장하되, 스케치 내부 상태와 전역 장면 카메라 상태를 직접 섞지 않는다.

## 6. 구현 단계

### 0단계: 기준선 확정 및 스키마 설계

- 현재 2D 모드와 CAD 가져오기 동작을 회귀 기준으로 고정한다.
- `SketchDocument`, `SketchEntity`, `SketchConstraint`, `SketchFeature` 스키마를 확정한다.
- 기존 `sketch-feature`, `cad-2d`, `cad-extrude-feature` 저장 형식의 마이그레이션 규칙을 작성한다.
- 스케치와 CAD의 좌표계·단위·원점·평면 방향 규칙을 문서화한다.

완료 기준: 스케치 문서를 UI 없이 생성·직렬화·복원할 수 있고, 기존 저장 데이터를 잃지 않는 변환 규칙이 있다.

### 1단계: 새 스케치 작업공간 뼈대

- 기존 도형 생성 버튼과 별도로 메인 작업공간에 `스케치 모드` 버튼을 추가한다.
- 기존 도형 생성 버튼은 기본 3D 도형 생성만 담당하고, 스케치 모드 진입·스케치 문서 편집을 담당하지 않도록 분리한다.
- 기존 `2D 모드` 표기는 `스케치 모드` 또는 `새 스케치`로 변경한다.
- 작업 평면 선택과 모델 면 선택을 추가한다.
- 스케치 전용 직교 카메라, 그리드, 원점, 축, zoom/pan을 구현한다.
- `새 스케치`, `스케치 완료`, `취소`를 도구·피처 생성과 분리한다.
- 기존 장면 선택·로봇 조작·OrbitControls와 스케치 입력을 명확히 분리한다.

완료 기준: 빈 스케치 문서를 만들고 평면을 바꾸며 안전하게 종료·재진입할 수 있다.

### 2단계: 기본 엔티티 편집

- 선, 폴리라인, 원, 호, 사각형, 타원, 구성선을 공통 엔티티로 지원한다.
- 요소 선택, 다중 선택, 창 선택, 이동, 회전, 복사, 삭제, 꼭짓점 편집을 추가한다.
- 끝점·중점·중심·교차점·그리드 스냅과 화면 내 hover 피드백을 추가한다.
- trim, extend, split, fillet/chamfer, offset을 명령 단위로 추가한다.
- 각 명령을 undo/redo와 연결한다.

완료 기준: 가져오지 않은 스케치에서도 CAD 기본 편집 작업을 마우스와 수치 입력으로 수행할 수 있다.

### 3단계: DXF를 스케치로 가져오기

- 현재 공통 `3D/CAD 파일 가져오기` 흐름과 분리해 스케치 툴바에 `CAD 삽입`을 둔다.
- DXF를 CAD2D IR로 읽은 뒤 SketchEntity로 변환한다.
- 레이어 유지, 원본 handle 유지, 단위 변환, 중심화/원점 기준 선택을 스케치 좌표계에 통합한다.
- `편집 요소`, `구성선`, `참조 도면` 변환 모드를 제공한다.
- 지원하지 않는 엔티티와 근사 변환을 가져오기 결과 요약에 표시한다.
- 대용량 DXF는 Worker에서 파싱하고, 스플라인·문자·치수·해치 등 지원하지 않는 엔티티는 변환하지 않고 결과 요약에 표시한다.

완료 기준: DXF를 장면의 독립 CAD 모델로 만들지 않고 현재 스케치 문서 안에서 선택·이동·수정할 수 있다. DWG는 지원하지 않는다.

### 4단계: 구속조건과 치수

우선순위가 높은 구속조건부터 단계적으로 추가한다.

1. coincident, horizontal, vertical, parallel, perpendicular
2. distance, horizontal/vertical distance, radius, diameter, angle
3. tangent, concentric, equal, symmetric, midpoint, fixed

- 치수는 단순 표시값이 아니라 문서에 저장되는 구속조건으로 만든다.
- 구속조건 추가 전후의 geometry 오류와 충돌을 검증한다.
- `완전 구속`, `부분 구속`, `과구속`, `해결 불가` 상태를 표시한다.
- 처음부터 모든 CAD 솔버 기능을 약속하지 않고, 각 구속조건의 지원 상태를 명확히 표시한다.

완료 기준: 저장·복구 후에도 치수와 구속조건이 유지되고, 요소를 수정할 때 관련 요소가 일관되게 갱신된다.

### 5단계: 3D 피처와 편집 연결

- `SketchFeature`를 독립적으로 저장한다.
- `ExtrudeFeature`와 `CutFeature`가 SketchFeature ID 및 프로파일 ID를 참조하게 한다.
- 스케치 수정 시 연결된 피처의 메시·충돌 형상·이름·선택 상태를 재생성한다.
- 열린 프로파일, 자기 교차, 중복 프로파일, 내부 구멍을 생성 전 검증한다.
- CAD에서 가져온 폐합 영역도 동일한 프로파일 생성 경로를 사용한다.

완료 기준: 피처 트리에서 스케치를 다시 열어 수정하고, 기존 돌출·컷 결과가 재계산된다.

### 6단계: 저장·복구·정리

- 작업 중 스케치와 완료된 스케치를 모두 workspace snapshot에 저장한다.
- 원본 DXF asset ID와 변환된 스케치 문서를 함께 저장한다.
- 새 스키마 버전과 이전 `sketch-feature`/`cad-2d` 형식의 migration을 추가한다.
- 기존 CAD 장면 모델 경로는 호환 복구용으로만 남기고 신규 흐름에서 제거한다.
- 기존 `main.js`의 CAD·스케치 이벤트를 새 모듈로 옮긴 뒤 중복 상태를 삭제한다.

## 7. 검증 계획

### 단위·결정론 검증

- 단위 변환(mm/inch 등), 좌표계 변환, 평면 변환, 원점 이동
- 선·호·원·타원·폴리라인의 길이·bounds·폐합
- 프로파일 추출, hole nesting, 자기 교차·열린 체인 탐지
- CAD 원본 handle·레이어·경고의 보존
- 스케치 문서 serialize/restore와 schema migration

### 상호작용 검증

- 새 스케치 → 평면 선택 → 엔티티 생성 → 선택·수정 → 완료·취소
- CAD 삽입 → 단위/변환 모드 선택 → 요소 수정 → 저장·복구
- 스냅 hover/click, 다중 선택, undo/redo, trim/offset
- 스케치 수정 → 돌출/컷 재생성
- 기존 3D 모델·로봇·충돌·모션 프로젝트 회귀

### 성능 검증

- 1,000개와 10,000개 엔티티 도면의 초기 표시·선택·pan/zoom
- 파싱 중 UI 응답성과 진행률
- undo/redo와 workspace 저장 용량
- CAD 원본과 스케치 변환 결과의 메모리 정리

현재의 `validate-2d-cad-import.mjs`와 스케치/CAD 뷰 검증은 유지하되, 새 스키마·변환·상호작용 검증을 별도로 추가한다. 정적 정규식 검증만으로 완료 판정하지 않고, 실제 브라우저에서 대표 DXF를 열고 편집·저장·복구하는 수동 또는 브라우저 자동화 검증을 포함한다. DWG 검증은 이번 범위에서 제외한다.

## 8. 위험과 대응

| 위험 | 대응 |
|---|---|
| DWG 요구 발생 | 이번 릴리스에서는 공식 지원하지 않고, 별도 브리지 도입을 후속 과제로 분리한다. |
| CAD 파일의 복잡한 블록·주석·해치 | 편집 형상과 참조 주석을 분리하고, 지원 범위를 파일별 capability로 표시한다. |
| 구속조건 솔버의 범위가 커짐 | 1차 릴리스는 우선순위가 높은 구속조건부터 제공하고, 과구속·미해결 상태를 숨기지 않는다. |
| 기존 저장 데이터 회귀 | 새 스키마를 별도 버전으로 두고, 이전 형식을 읽기 전용 호환 어댑터로 먼저 지원한다. |
| 33,000줄 이상인 진입점의 회귀 | 단계마다 모듈 단위 테스트와 브라우저 회귀 검증을 통과시킨 후 다음 단계로 이동한다. |
| 스케치와 3D 장면 입력 충돌 | 스케치 viewport 입력, 장면 선택 입력, OrbitControls 입력을 명시적인 모드 상태로 분리한다. |

## 9. 1차 릴리스의 범위 제안

1차 목표는 “완전한 SolidWorks/Fusion 복제”가 아니라, 다음 경험을 끊김 없이 제공하는 것이다.

- 기존 도형 생성 버튼과 분리된 `스케치 모드` 버튼으로 진입
- XY/YZ/ZX 또는 3D 면에서 스케치 시작
- 선·폴리라인·원·호·사각형·구성선 생성 및 편집
- 기본 스냅과 수치 치수
- DXF의 주요 선형/곡선 요소를 스케치 요소로 삽입
- 선택·이동·삭제·trim·프로파일 검증
- 스케치 저장·복구
- 스케치를 참조하는 돌출·컷과 재편집

타원의 정밀 편집, 고급 구속조건, 패턴·미러, 도면 주석 편집, DWG 지원은 후속 범위로 둔다.

## 10. 완료 판정

아래 항목을 모두 만족해야 전면 개편 완료로 판정한다.

- `스케치 모드` 버튼이 기존 도형 생성 버튼과 분리되어 동작한다.
- 스케치 모드가 독립적인 스케치 문서 편집 흐름으로 동작한다.
- DXF를 스케치 안으로 가져와 선택·수정·구속할 수 있다.
- DWG는 공식 지원 파일 목록과 가져오기 UI에 포함하지 않는다.
- CAD 원본 레이어·단위·원본 식별자와 변환 경고가 보존된다.
- 스케치와 돌출·컷이 분리된 피처 관계로 저장되고 다시 편집된다.
- 작업 중 스케치가 저장·복구된다.
- 기존 3D 모델 가져오기, 로봇 조작, 충돌·모션·프로젝트 복구가 회귀하지 않는다.
- 단위·geometry·변환·저장·브라우저 상호작용 검증이 모두 통과한다.

## 11. 첫 구현 작업

다음 구현 작업은 기존 UI를 바로 뜯어고치는 것이 아니라, 아래 순서로 시작한다.

1. `SketchDocument`와 `SketchEntity` 스키마를 별도 모듈로 만든다.
2. 현재 선·사각형·원·CAD 주요 엔티티를 새 스키마로 변환하는 어댑터를 만든다.
3. 빈 스케치 작업공간과 직교 카메라/평면 좌표계를 먼저 연결한다.
4. 기존 돌출·컷은 새 문서를 참조하도록 연결하되, 기존 저장 형식은 읽기 호환으로 유지한다.
5. 기존 도형 생성 버튼과 분리된 스케치 모드 버튼을 먼저 연결한다.
6. DXF CAD 삽입을 새 스케치 작업공간에 연결한 뒤, 기존 장면 CAD 패널을 단계적으로 축소·제거한다. DWG 경로는 추가하지 않는다.

이 순서를 지키면 “CAD 파일이 장면에 잘 보이는가”와 “CAD가 실제 편집 가능한 스케치가 되었는가”를 분리해서 검증할 수 있다.
